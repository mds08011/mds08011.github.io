Encoding SVG as a Data URI, and Why URL-Encoding Usually Wins

July 2026

The Problem

The SVG base64 embedding sandbox on this site is a static demo with three hardcoded examples. It shows how embedding an SVG (Scalable Vector Graphics file) inside an <img> data URI works and that scripts inside the SVG do not run, but it does not let you convert your own SVG. This companion page, SVG Data URI Encoder, takes an SVG you paste in and gives back ready-to-use data URI strings.

How it works

Open any .svg file in a plain text editor, copy the <svg>...</svg> markup, and paste it into the page. It renders a live preview through an actual <img> data URI, shows both Base64 and URL-encoded outputs side by side with their byte sizes, and gives you copyable HTML <img> and CSS background-image snippets. It also adds the required xmlns attribute if your SVG is missing it (browsers will not render an SVG data URI without it) and can strip comments and extra whitespace first.

Why URL-encoding is usually smaller than Base64

Base64 is the default encoding most people think of for data URIs, and it turns every 3 bytes into 4 characters (roughly a 33% size increase) [1]. Because SVG files are mostly plain text, leaving the normal characters alone and percent-escaping only the characters a URL cannot contain (the minimal scheme popularized by Yoksel [2]) usually produces a smaller string that is still readable in HTML or CSS. The page shows both sizes so you can see which one is smaller for your file.

A few encoding notes
  • The Base64 option encodes text as UTF-8 first so SVGs with non-ASCII characters work without breaking btoa.
  • The URL-encoded option swaps double quotes for single quotes (so the URI fits inside double-quoted HTML/CSS attributes), collapses whitespace between tags, and escapes only %#()<>?[\]^`{|} and newlines [2].
  • Scripts inside an SVG do not run when loaded via <img> or CSS url() (the same behavior shown in the sandbox). Pasting raw <svg> directly into an HTML document is not sandboxed and can run scripts.
  • Data URIs make the most sense for small icons and simple graphics. Larger SVGs bloat the HTML/CSS file and cannot be cached separately by the browser, so linking them as normal files is better.

Everything runs locally in your browser (saving your last input in localStorage). If you want a PNG or JPEG image out of an SVG instead of a data URI, use the SVG to JPEG/PNG page.
