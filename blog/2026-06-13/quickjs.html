Running QuickJS via WebAssembly

June 2026

Executing untrusted JavaScript paradigms generally requires a rigid server-side container orchestration system to prevent host compromise. A more secure, minimal-latency approach leverages a client-side WebAssembly (WASM) build of the QuickJS engine. This compiles an entirely independent JavaScript runtime directly within the user's browser thread, guaranteeing complete isolation from the native DOM context.

This implementation utilizes the quickjs-emscripten library [3] to instantiate the isolated execution context. Native functions, such as console.log() and a synchronous fetch equivalent, are explicitly bound into the WASM instance prior to evaluation. Code inputted into the user interface is executed using vm.evalCodeAsync() [1][2].

To improve usability, state retention is achieved by pushing the raw, URI-encoded script directly to the URL hash fragment. Pressing Ctrl + Enter (Cmd + Enter on macOS) runs the code in the editor [2].

The tool: QuickJS in WebAssembly.

Analyzing the required WASM bundle

To peek at the first five lines of the bundled script from a Linux or macOS terminal (do not type the $; curl -s downloads quietly and | head -n 5 prints only the first five lines):

$ curl -s https://cdn.jsdelivr.net/npm/quickjs-emscripten@0.31.0/dist/index.global.js | head -n 5
