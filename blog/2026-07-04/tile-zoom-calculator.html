Slippy Map Tile and Zoom Calculator

July 2026

Web maps divide the world into square 256-pixel raster tiles addressed by zoom level, column, and row (z/x/y) in the Web Mercator projection (EPSG:3857). This calculator converts between geographic coordinates (latitude and longitude, or lat/lon, in decimal degrees) and OpenStreetMap (OSM) slippy tile addresses, computes ground resolution and approximate screen scale, and formats the tile's bounding box (bbox) for mapping tools and Overpass queries.

For a given coordinate and integer zoom level, the forward OSM slippy tile indices are [1]:

x = ⌊((lon + 180) / 360) · 2^z⌋,   y = ⌊(1 − ln(tan(φ) + sec(φ)) / π) / 2 · 2^z⌋

Here lon is longitude in degrees (−180 to 180), φ is latitude in radians (lat · π / 180), z is the zoom level (0 to 22), and ⌊ ⌋ is the floor function (rounding down to the nearest integer). Tile x increases eastward and tile y increases southward. Evaluating the inverse equations at (x, y) gives the tile's northwest corner in degrees, and evaluating at (x + 1, y + 1) gives the southeast corner to define the tile bounding box [1].

For standard 256-pixel tiles, ground resolution is R_g = 156,543.034 · cos(φ) / 2^z meters per pixel, where 156,543.034 m/px is the equatorial circumference divided by 256 pixels (2πR / 256 for spherical Earth radius R = 6,378,137 m) [2]. Because of the cos(φ) term, a given zoom level covers less ground per pixel at mid-latitudes such as California than at the equator. Approximate screen scale is estimated at 96 dots per inch (dpi) as scale = R_g · 96 / 0.0254, and the calculator prints a reference table from zoom 10 through zoom 20 for the entered latitude [2].

Many geographic tools format a bounding box as W, S, E, N (minimum longitude, minimum latitude, maximum longitude, maximum latitude). The Overpass API (the read-only query interface for OpenStreetMap data) expects (S, W, N, E) (minimum latitude, minimum longitude, maximum latitude, maximum longitude) [3]. Using the wrong coordinate order may silently query a different region or return empty results. The calculator outputs both labeled strings with copy buttons, and the (S, W, N, E) output matches the input format of the OSM Tag Helper.

Notes and limits
  • Tile Map Service (TMS) numbers tile rows from south to north rather than north to south. Convert from OSM/XYZ to TMS with y_tms = 2^z − 1 − y [1].
  • Web Mercator cuts off at ±85.0511° latitude, where the projected map forms a square. Latitudes beyond that limit are clamped.
  • Bulk downloading map tiles from OpenStreetMap's public tile servers is restricted under the OpenStreetMap Foundation Tile Usage Policy [4]. Use tile calculations for coordinate checks, resolution planning, and Overpass queries.
  • The calculator is a single offline HTML file with no external dependencies. Inputs are saved in your browser's localStorage (local browser storage on your device) until cleared.
