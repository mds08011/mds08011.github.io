Logging Tracer Study Samples with One-Tap Timestamps

July 2026

A drinking-water tracer study measures how long water actually takes to pass through a disinfection contact basin or clearwell by tracking a chemical tracer (often a step change in chlorine residual, the remaining free or total chlorine concentration) at the outlet [1]. The test data are used to find T10 (the detention time at which 10% of the tracer reaches the outlet, min) and the baffling factor BF = T10 / HDT, where HDT = V / Q is the theoretical hydraulic detention time (min), V is the basin water volume (gal), and Q is the plant flow rate (gpm) [1].

During a study, grab samples (individual water samples collected at specific times) are tested for chlorine concentration in parts per million (ppm, equivalent to mg/L in dilute water) using a benchtop meter or field titration kit, while flow rates are recorded by the plant's Supervisory Control and Data Acquisition (SCADA) historian (the automated process data logger). This tool provides a large LOG SAMPLE TIME button that records the device clock to the second and opens a table row with a blank input for the chlorine concentration, so sample times can be recorded when the bottle is filled and concentrations entered once the measurement is ready.

Rows display newest-first on screen, persist in browser localStorage (local storage on the device) with a confirmation dialog (confirm()) before clearing, and export chronologically as a comma-separated values (CSV) file using the browser's Blob file download API. Like the Stormwater Pollution Prevention Plan (SWPPP) rain tracker, the logger avoids JavaScript's toISOString() method because it outputs Coordinated Universal Time (UTC), which shifts US local times by several hours and can shift the calendar date. Instead, timestamps are built from local clock components, where pad(n) adds a leading zero to single-digit numbers and getMonth() + 1 converts JavaScript's 0-to-11 month index to 1-to-12:

function pad(n) { return n < 10 ? "0" + n : "" + n; }
var d = new Date(ms);
var ts = d.getFullYear() + "-" + pad(d.getMonth() + 1) + "-" + pad(d.getDate())
  + " " + pad(d.getHours()) + ":" + pad(d.getMinutes()) + ":" + pad(d.getSeconds());
Notes and limits
  • Clock offset: Before collecting the first sample, compare the phone or tablet clock against the SCADA historian clock and record any difference. Applying that constant offset during analysis keeps clock skew from distorting T10 and the baffling factor [1].
  • Sampling cadence: Collecting samples on a fixed interval (such as every 2 minutes) across the breakthrough curve (the period when outlet tracer concentration rises sharply) and spacing samples farther apart along the tail (where concentration levels off) simplifies plotting and data alignment [1].
  • Joining with flow data: Export the CSV and align it with the historian's flow export on the adjusted timestamp column in a spreadsheet (for example, using XLOOKUP or VLOOKUP in Excel) or a script (such as pandas.merge_asof in Python).
  • Regulatory protocols: Check the governing state drinking-water primacy agency protocol for tracer selection, sampling intervals, and T10 calculation rules, as state requirements may add to EPA guidance.
  • Browser storage: The logger is a single HTML page written in plain JavaScript that runs offline. Clearing browser site data or switching devices removes localStorage entries, so export the CSV after completing a study.
