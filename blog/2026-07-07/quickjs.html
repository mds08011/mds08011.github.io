Running QuickJS via WebAssembly

July 2026

Executing untrusted JavaScript paradigms generally requires a rigid server-side container orchestration system to prevent host compromise. A more secure, minimal-latency approach leverages a client-side WebAssembly (WASM) build of the QuickJS engine. This compiles an entirely independent JavaScript runtime directly within the user's browser thread, guaranteeing complete isolation from the native DOM context.

This implementation utilizes the `quickjs-emscripten` library to instantiate the isolated execution context. Native functions, such as console.log() and a synchronous `fetch` equivalent, are explicitly bound into the WASM instance prior to evaluation. Code inputted into the user interface is securely executed using vm.evalCodeAsync() [1].

To improve usability, state retention is achieved by pushing the raw, URI-encoded script directly to the URL hash fragment. Execution interrupts are seamlessly managed through keyboard shortcuts, mapping Ctrl + Enter to the evaluation subroutine [2].
